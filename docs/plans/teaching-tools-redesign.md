## 0 结论先行

1. 现在 5 个工具共用一套「左边表单 + 右边对话」的壳：产出是**聊天文字**，教师拿到还得自己搬。改造的核心不是换皮肤，而是给每个工具一条 **选料 → 草稿（可改）→ 成品（文件/图片/结构化数据）→ 交付** 的流水线。
2. 作业卡片的真正瓶颈不在版式，在**三件缺失**：没有图片导出、没有发群通道、没有把「班级 + 教材 + 作业情况」喂进生成过程（`desktop/src/renderer/src/pages/TeachingPage.tsx:298-315` 只收「题目来源/版式/题量」三字段）。
3. 课件质量的天花板在渲染器：`agent/tools/pptx/builder.py` 只有「标题 + 项目符号」，3 个纯色主题（`agent/tools/pptx/themes.py:22-28`），无配图、无版式变化。要么换成模板驱动的 HTML deck（本地已有 MIT 的 `html-ppt`：36 主题 / 15 套整册模板 / PNG 导出脚本），要么用 `pptxgenjs` 走 Anthropic `pptx` skill 的成熟套路。二选一是 ADR，不是实现细节（§7）。

## 2 设计原则

1. **产出物决定布局。** 教案是稿纸，课件是幻灯片轨道，作业卡片是竖版手机图，建议是数据事实 + 清单，计划是周次表。不再一律「表单 + 聊天」。
2. **必须有可改的中间态。** 一步到成品没人用：教案先出大纲、课件先出页纲、卡片先出题目清单、计划先出周次表；改完再渲染。中间态是结构化 JSON，不是散文。
3. **吃真实数据，不吃自由文本。** 班级 / 单元 / 教材 / 作业 / 成绩 从 store 读；教师只补「这一次的意图」（一句话）。
4. **成品要能出去。** 每个工具页底部固定一条交付条：下载 / 发群（图片、文字）/ 写入知识库 / 写入进度。没有交付的产出等于没产出。
5. **提示词单一来源。** 输出契约定在 skill 里；页面只传结构化参数，不再各自复述一遍输出结构。

## 3 逐页设计

### 3.1 教案生成（`plan`）— 稿纸 + 大纲

定位：把一个单元的教材内容压成一节可执行的课。产出 `knowledge/教案/<slug>.md`。

```
┌ 选料条：学段 学科 教材 [单元 ▾ 来自 knowledge/教材] 课型 课时 ──── 从既有教案复用 ▾ ┐
├──────────────┬──────────────────────────────────────────────────────────┤
│ 参考素材      │ 大纲（可改、可拖顺序、每行可折叠成一段）                    │
│ ·教材原文     │  1 教学目标 ……  [重写] [加一条]                            │
│ ·课程标准     │  2 重难点   ……                                            │
│ ·同单元旧教案 │  3 过程（环节/时长/师生活动/意图）……                       │
│ ·上次作业反馈 │                                                          │
│              │ ─── 生成全文 → 稿纸视图（Markdown 富文本，可直接改）───     │
└──────────────┴──────────────────────────────────────────────────────────┘
交付条：[保存到知识库] [做课件 →（跳 3.2，带本教案）] [导出 md/docx]
```

要点：
- 教材原文在左栏可点开（`/api/knowledge/read`），生成时作为引用来源，页面上标出处。
- 「做课件」把教案路径直接带进 3.2，避免二次选择。
- 大纲 → 全文两段式，第一次生成只出大纲（成本低、改起来快）。

验收：同一单元连做两次，第二次能复用上次教案并在左栏出现；产出文件在 `knowledge/教案/`；大纲与全文结构一一对应。

### 3.2 课件生成（`courseware`）— 缩略图轨道 + 大预览 + 讲稿

定位：教案 → 一套能直接放的课件。产出 HTML deck（预览/发群/导出 PNG）与 `.pptx`（教师二次编辑）。

```
┌ 源：[本单元教案 ▾ / 上传 / 从 3.1 带回]  模板：[讲授/活动/复习/…主题 ▾]  页数 12 ─────┐
├─────────┬─────────────────────────────────────────────┬────────────────────┤
│ 页轨     │ 大预览（16:9，所见即所得）                    │ 讲稿 / 备注（教师口播）│
│ 1 封面   │                                              │ 这一页怎么讲、问什么、│
│ 2 目标   │                                              │ 几分钟；可编辑        │
│ 3 …      │                                              │                    │
│ [+ 加页] │                                              │ [换版式 ▾] [重画此页]│
├─────────┴─────────────────────────────────────────────┴────────────────────┤
交付条：[导出 .pptx] [导出 PNG 包] [放映] [发到班级群]
```

要点：
- **页纲先确认**：生成 → 一页一行（页码/标题/要点），可增删改序 → 再渲染，避免整册重来。
- 版式不是自由画布：每页从模板库的版式里选（封面/目标/三段/对比/图示/时间线/表格/小结），渲染器保证不溢出。
- 图片：先用 `image-generation` skill 出图并落盘，再嵌进页面（离线可选；缺 key 时留占位框并在讲稿写「此处用课本 Pxx 图」）。
- 讲稿独立于页面文本，导出 pptx 时写进 notes。

验收：一次生成 12 页，任一页可单独重画而其余页不变；导出的 `.pptx` 在 PowerPoint/Keynote 打开无字体错乱；PNG 包每张 1920×1080。

### 3.3 作业卡片（`card`）— 班级胶囊 + 一句话 + 手机版预览 + 发送条

定位（用户原话）：**给每个班级一段话（课后作业）→ 基于知识理解作业情况 → 总结作业 → 生成精致的作业卡片 → 发到学生群里**。所以这页不是「做题器」，是「一次家庭作业的发布流程」。

```
┌ 班级：[七(3) ×] [七(4) ×]  [+]            本次作业：[基础巩固 ▾] 截止：周四 ────────┐
├ 一句话说清这次作业：________________________________________________________________ │
├ 依据（自动勾选，可取消）：教材 Unit 3 词汇 ▸ / 上次作业错得多的 3 个知识点 ▸ / 题库 ─┤
├──────────────┬──────────────────────────────────────────────────────────────────┤
│ 题目清单      │ 卡片预览（竖版 1080×1440，手机上就是一张图）                        │
│ 1 词汇 基础 ✓ │   ┌──────────────────┐                                           │
│ 2 句型 基础 ✓ │   │  七(3)班 · 英语     │ ← 同一份模板，班级/日期/二维码/署名自动填 │
│ 3 句型 提升 ✓ │   │  Unit 3 课后作业    │                                           │
│ 4 阅读 挑战   │   │  ……题目缩略……      │                                           │
│ [重排][分层]  │   └──────────────────┘                                           │
│              │ 备注给家长的一句话（自动生成，可改）：今晚 20 分钟，重点是 ___        │
├──────────────┴──────────────────────────────────────────────────────────────────┤
交付条：[导出图片] [打印 A4] [发送到 七(3) 群] [发送到 七(4) 群] [存为作业记录]
```

要点：
- 「基于知识理解作业情况」= 读最近一次同单元作业/考试成绩分布（`agent/teaching/store.py` scores + homework records），自动选出「错误率高的 3 个点」放进依据。
- 分层：基础 / 提升 / 挑战三档，默认按班级成绩分位自动配比，教师可一键改成全基础。
- **发送是核心动作**：每班绑定一个群机器人 webhook（见 §6）；发送内容 = 卡片图 + 一句总结文案；发出后写一条发送记录（时间/班级/图/文案），页面底部显示最近发送。
- 答案版单独一张，不进学生群。

验收：从选班到发出图 ≤ 4 次点击；卡片图在微信里点开清晰（1080 宽）；发送失败有明确原因（webhook 未配 / 网络 / 群不存在）。

### 3.4 教学建议（`advice`）— 数据事实 → 判断 → 可采纳行动

定位：不是写一篇教育散文，而是读这个班的数据，给出能落地的 3 条行动。

```
┌ 班级 [七(3) ▾]  单元/课题 [Unit 3 ▾]  关注 [课堂参与 / 分层 / 作业 ▾]  ─── 时间范围 ▾ ┐
├ 事实（系统算，可点开看明细）─────────────────────────────────────────────────────┤
│ 进度：落后计划 2 课时 · 作业一次都没交 5 人 · 上次单元测 均分 78，阅读题得分率 41%    │
├ 判断与行动（每条：[采纳 → 生成任务] [追问]）──────────────────────────────────────┤
│ ① 阅读题是主因 → 明早 10 分钟限时读，材料取 Unit 3 第二篇 ……                        │
│ ② 5 人连续未交 → 课代表一对一，今天放学前 ……                                       │
├ 追问对话（沿用 EmbeddedChat，可带上下文继续问）─────────────────────────────────────┤
└ 交付条：[全部采纳 → 任务看板] [导出建议单] [发给自己]
```

要点：
- 事实区是**算出来的**（进度差值、未交人数、得分率），不是模型描述；模型只做「判断 + 行动」。
- 每条建议可一键变任务（已有任务看板 API），否则建议留着等发霉。
- 追问时把事实区作为上下文一起带上。

验收：事实区的数字与 进度/作业/成绩 页面完全一致；采纳后看板出现同名任务。

### 3.5 教学计划（`schedule`）— 周次表编辑器 + 与进度/课表对齐

定位：把学期计划变成**结构化数据**（写进教学进度），不是一张 markdown 表格。

```
┌ 学期 2026-2  教材 [七上 ▾]  周数 18  起始周 [第 1 周 ▾]  每周课时 5 ──────────────┐
├ 周次表（可直接编辑：单元 / 课题 / 课时 / 目标 / 评价）                          │
│ 第1周 │ Unit 1 │ 听说 │ 2 │ …  │ …  │  [自动排] [压缩到 16 周] [留出期中复习周] │
│ 第2周 │ …                                                                      │
├ 右栏：与课表 / 进度的对齐情况                                                   │
│ · 课表里七(3) 本周只有 4 节 → 计划 5 节，冲突                                       │
│ · 进度里 Unit 1 已授 2/2                                                         │
└ 交付条：[写入教学进度] [导出表格] [生成周历图片]
```

要点：
- 输出的主形态是 JSON（weeks[]），落进 `teaching/progress`，其余形态都是导出。
- 冲突检测：与课表节数、与已授进度、与节假日（可后置）。
- 「压缩到 N 周」是常用操作，要有（教师最常改的就是总周数）。

验收：写入进度后，首页「教学进度」出现这些课题且 `planned_periods` 正确；冲突提示可复现。

## 6 交付：发群怎么落地

现状：所有 channel 都是「收到消息 → 回复」，没有主动推送能力（`channel/*/…_channel.py` 的 `send(reply, context)`）。因此新增一条**班级群机器人**通道，而不是复用对话 channel：

- 数据：`teaching/groups.json` → `{class_id, kind: wecom|feishu|dingtalk, webhook_url, name}`
- 发送：POST webhook。图片走 base64/md5（企微群机器人支持 `image` 类型）、文字走 markdown；失败按 HTTP/errcode 给出中文原因
- 安全：webhook URL 含密钥，只存本地、日志脱敏
- 备选（不做初版）：复用企业微信应用消息 API 按 chat_id 群发，需要企业资质

初版只做图片 + 一句话文案，不做富文本排版。

## 7 待决策（ADR 候选）

1. **课件以谁为源**：HTML deck（好看、导出图/PDF、离线字体需自带）vs `.pptx`（教师可改、跨机字体风险）vs 双出（HTML 预览 + pptx 交付）。建议：双出，HTML 为源。
2. **HTML deck 用不用 `html-ppt`**：MIT、36 主题、15 套整册模板（含 `course-module`）、自带 headless PNG 导出脚本；代价是 CDN webfonts 要换成本地字体或系统字体栈（离线要求）。
3. **pptx 用不用 `pptxgenjs`**：Electron 主进程已带 node，无需新运行时；Anthropic `pptx` skill（`anthropics/skills` 仓库，19.3 万星）用它 + OOXML 直接改，成熟度高。**不可用 PPTist（AGPL-3.0，传染）**。
4. **发群走群机器人 webhook**（快、免资质、只能发不能收）vs 应用消息 API（需企业资质收集 chat_id）。
5. 卡片图片尺寸：1080×1440（微信朋友圈/群图观感）vs A4 比例（打印同源二选一）。

参考（2026-11 实测 GitHub API）：`anthropics/skills` 193k★、`slidevjs/slidev` 49.4k★ MIT、`marp-team/marp` 12.7k★ MIT、`gitbrent/PptxGenJS` 6.4k★ MIT、`presenton/presenton` 11.9k★ Apache-2.0、`pipipi-pikachu/PPTist` 9.5k★ AGPL-3.0、本地 `~/.agents/skills/html-ppt` MIT。

## 9 术语表（本设计新增/收紧）

- **草稿（draft）**：结构化中间产物（大纲/页纲/题目清单/周次表），可编辑，尚未渲染成文件。
- **成品（deliverable）**：落盘文件或可发送的图/文，带路径与元数据。
- **交付条（DeliverBar）**：页面底部固定的成品出口（下载/发群/入知识库/入进度）。
- **依据（evidence）**：生成前勾选的教材/题库/学情来源，页面上可展开原文。
- **群机器人（group bot）**：班级绑定的 webhook，只发出不接收，用于把成品推到学生群。
- **事实条（facts）**：由系统算出的数字（进度差、未交人数、得分率），与模型措辞严格分开。
