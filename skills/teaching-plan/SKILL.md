# 教学计划

把「学期 / 单元范围」变成一张能照着走的周计划表，必要时拆成任务卡跟进。

## 1 收输入

- 学期与起止日期（或第几周开始）。
- 教材版本、册次、单元范围（全册 / 某几个单元）。
- 周课时、每课时时长、总周数。
- 校历约束：期中、期末、月考、节假日、运动会等占用的课时。
- 已有进度：哪些单元已讲、讲到第几课时（可从 `knowledge/教案/` 的文件名与修改时间推断，但推断结果要向教师确认）。

不确定的项最多问两个关键问题（单元范围、周课时），其余按常规取值并在计划表脚注写明假设。

## 2 计划表结构

```markdown
# <学期> 教学计划（<教材>）

> 假设：每周 N 课时，共 M 周；第 X 周期中，第 Y 周期末。

| 周次 | 日期 | 单元 / 课题 | 课时 | 目标 | 评价方式 | 作业 |
|---|---|---|---|---|---|---|
| W1 | 9/1–9/5 | Unit 1 第 1–2 课时 | 2 | 能介绍自己与同伴 | 口头展示 | 单词卡 |
| … | | | | | | |

## 单元课时分配
- Unit 1：5 课时（听说 2 / 阅读 2 / 写作 1）

## 弹性与风险
- 期中前若少 2 课时，优先压缩 Unit 2 的写作讲评。
```

规则：

- 课时总数 = 可用周数 × 周课时，扣掉考试与活动周后必须自洽；表脚注写出算式。
- 每行有可检验的目标（「能复述课文第 2 段」），不写「学习 Unit 3」。
- 每个单元给出听说/阅读/语法/写作的课时拆分，合计等于该单元分配课时。
- 复习与讲评单独占行，不藏在单元行里。
- 表内不写真实学生姓名；班级信息写到脚注。

## 3 拆成任务卡

教师要把计划落到看板时，逐周拆卡（每卡 0.5–2 小时可完成）：

- 如果当前环境提供 `task_board` 工具，用它在看板上建卡，字段：标题、截止日、状态（待办/进行中/完成）、备注（关联单元与周次）。
- 如果环境没有 `task_board` 工具，输出 Markdown 任务清单，标题格式 `W3 完成 Unit 2 阅读课备课`，并说明「看板可用后我可以直接建卡」。
- 每张卡只对应一个可交付物（一份教案、一份课件、一套作业卡片），不要写「准备 Unit 2」这种大卡。
- 建卡后回读看板确认卡片存在，再报告卡数与首末截止日。

## 4 落盘

1. 用 `write` 写到 `knowledge/教学计划/<学期>-<教材>-<范围>.md`，例如
   `knowledge/教学计划/2026春-人教七下-全册.md`；目录不存在先 `mkdir -p knowledge/教学计划`。
2. 回读确认文件存在，报告路径、总周数、总课时、覆盖单元。
3. 计划调整时改同一个文件并保留「变更记录」小节（日期 + 调整内容），不要另起新文件。
